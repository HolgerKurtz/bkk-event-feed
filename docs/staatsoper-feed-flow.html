Staatsoper Feed Flow

How python3 pagefeed.py staatsoper turns the opera's calendar into the Google Ads page feed and the Meta product feed, and where every value comes from. Numbers are from the run on 11.11.2026.

Calendar page Production page (cached) wsrv.nl image proxy Worked out by the script

The run, step by step

1

Download the calendar

die-hamburgische-staatsoper.de/de/kalender

One request. The page lists every performance of the season (about 420), each with date, time, venue, category, title, subtitle, ticket button and price categories. It is about 150 KB compressed.

2

Read each performance

one block per performance
  • Performances that have already started (Berlin time) are skipped.
  • The ticket button decides availability: Ausverkauft or Aktuell keine Karten means sold out. Tickets, VVK: … and everything else count as available.
  • Prices come from the tag line, e.g. 7€ 13€ 21€ … 122€. A price in grey (tag--disabled) is a sold-out category and is ignored for the lowest price.
3

Group performances by production page

420 performances → 96 pages
  • Available: at least one future performance is not sold out.
  • Date, time, venue: from the next available performance (or the next one, if all are sold out).
  • Price: the lowest bookable price across available performances. If none is bookable, the lowest listed price.
  • ID: the end of the URL, e.g. 1911-wunderland.
4

Look up image and description

production page, e.g. /de/programm/ballett/1911-wunderland
  • Image: the page's og:image. Without one, the first photo of the page's own "Impression" gallery.
  • Additional images: the other photos of that gallery, up to 20. Teaser sliders for other events and sponsor logos on the same page are ignored.
  • Description: the page's meta description. Without one, the subtitle from the calendar, then the title.
  • Stored in feeds/staatsoper-details.json. Only new pages are fetched, and known pages again after 30 days. The first run made 96 requests (one per second). A normal day makes 0–5.
5

Convert the image to JPEG

wsrv.nl/?url=…&w=1200&output=jpg

The Staatsoper only serves WebP, which Meta rejects. The feed links each image through wsrv.nl, which converts it to a 1200 px JPEG when Meta fetches it. Nothing is stored here. Each run tests one converted image and fails if it doesn't come back as a JPEG.

6

Check, then write both files

nothing is written if a check fails

If any check below fails, the old files stay online and the GitHub run fails, which sends an email.

What comes out

95 URLs Page feed for Google Ads feeds/staatsoper.csv

Every page with at least one available performance, labelled oper, ballett, konzert or sonstiges. Same content as before this change.

58 items Product feed for Meta feeds/staatsoper.xml

One item per page. Sold-out pages stay in as out of stock (none today). 26 items carry extra gallery photos, 269 in total.

38 left out Product feed only still in the page feed

29 side events with no image of their own (tours, school programmes, talks, kids' concerts) and 9 pages with no price listed yet, e.g. Matthäus-Passion and Scirocco. Those 9 join the product feed once the site shows a price.

Checks before anything is written

  • At least 100 performances found in the calendar.
  • At least half the performances have a ticket button.
  • There are URLs under /oper/, /ballett/ or /konzert/.
  • Every URL has a label.
  • Neither feed shrinks by more than 50 % compared with the last run.
  • No more than 50 % of pages lack a price or image (today 40 %).
  • The first converted image comes back as 200 image/jpeg.
  • Every item has an ID, title and link.

Switching it on and off

ACTIVE = True at the top of clients/staatsoper.py. Set it to False and the daily run skips the Staatsoper while its last feeds stay online. python3 pagefeed.py staatsoper still runs it by hand.
